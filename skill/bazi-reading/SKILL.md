# 八字解读 —— Dan 的方法论

## 工具调用（强制，按序执行，缺一不可）

本 skill 的每次执行都必须实际发起下列调用。「凭记忆」跳过任何一步 = 整轮作废。

| # | 步骤 | 工具 | 要求 |
|---|---|---|---|
| T1 | **排盘** | Bash: `node engine/cli.js --date=… --time=… --gender=… --city=…` | 必须实跑引擎拿 chart.json。**禁止手算任何干支**。没有出生地经度时必须在输出里带上引擎给的 warning |
| T2 | **排盘交叉校验** | 会话中存在万年历/排盘类 MCP 工具时必须调用 | 四柱逐柱比对；不一致 → 停止，报告差异，不许继续断 |
| T3 | **知识检索（RAG）** | Read `references/glossary.md`、`references/boundaries.md`；配置了向量库/记忆类 MCP 时，用「日主X 月令Y 强弱Z」为 query 检索 | 断语落笔前必须完成。boundaries 是红线，glossary 是翻译表 |
| T4 | **相似案例** | Glob + Read `cases/*/`，找同日主五行或同强弱方向的 2 个已有案例 | 作为 few-shot 参照；`cases/` 为空时记录「无案例可参照」 |
| T5 | **写盘入库** | Write `cases/<id>/chart.json` + `reading.json` + `final.json` | 每张算过的盘必须落盘，作为回归测试与未来 RAG 语料 |
| T6 | **动画脚本** | 按 `anima/stage/DSL.md` 生成 | 见下——这是输出的一部分，不是可选项 |

### T6 动画脚本的硬性要求

- `final.json` 的**每个 block 必须带 `anim` 字段**（DSL 脚本），一个都不能少
- 用户后续提问的回答 = **一段 10–20 秒循环动画 + 一条静态字幕**，不是文字。
  文字只出现在 caption（≤50 字，解释画面在说明什么）
- 脚本必须能通过 `Stage.validateScript()`（sprite/behavior 白名单、caption 必填、duration 钳制 10–20s）
- 触碰 boundaries 红线的问题 → 固定返回 `hero.shrug + ban` 脚本，caption 温和拒答

## 铁律（违反即整轮作废）

1. **绝不自己算干支。** 四柱、藏干、大运、节气一律只从 `chart.json` 读。
   凡是 chart.json 里没有的干支信息，回答「引擎未提供」，不要推算。
2. **每一层从头完整重算，不许打补丁。** 见下文「迭代收敛」。
3. **每条断语必须带 `evidence`**，指向盘中具体位置（哪个柱、哪个藏干、哪个神煞、哪条冲合）。
   编不出证据的话就不要说。
4. **娱乐向输出。** 术语必须翻译成人话（翻译表见 `references/glossary.md`）。
   健康/寿命/灾祸/婚变类断语受 `references/boundaries.md` 约束。

## 核心：迭代收敛，不是叠加

**错误做法**（模型的默认倾向）：先给个结论，后面每来一个新维度就在结论上补一句。
→ 模型会维护自己上一轮说过的话，越补越歪。

**正确做法**：每一层带着「到此为止所有已解锁的维度」**从头写一份完整的解读**，
然后跟上一版做 diff。上一版只是**参照物**，不是底稿。

> 写 V4 的时候，不要看着 V3 改。把 V3 收起来，用 V1–V4 全部维度重新想一遍，写完再去跟 V3 对。

### 层间权重（Dan 确认）

- **V3 权重高于 V2，但 V2 仍参与。** 精读优先于粗读，粗读提供全局背景。
  两者冲突时以 V3 为主，但必须在 `conflicts` 里显式记录，不许悄悄覆盖。
- **V4/V5/V6 是补充性质**，不推翻 V1–V3 定下的骨架（身强弱、五行盈缺、宫位），
  但它们的加入会让整套解读重算一遍，侧重和细节会变。
- **`chart.relations`（刑冲合害会）全程可用**，不属于任何单独一层——它是背景约束。

## 宫位（Dan 确认）

**柱位宫**

| 柱 | 宫 | 年龄段 |
|---|---|---|
| 年柱 | **父母宫**（祖辈、出身背景） | 0 → 起运岁 |
| 月柱 | 兄弟宫（家庭环境、青年际遇） | 起运 → +20 |
| 日柱 | 配偶宫（日干=自己，日支=配偶） | +20 → +40 |
| 时柱 | 子女宫（晚年、事业终局） | +40 → 终 |

年龄段由引擎按起运岁数算好，直接读 `palaces.byPillar[*].ageFrom/ageTo`，**不要自己算**。

**十神六亲** —— 亲戚、朋友、长辈**不占柱位**，走十神推。
读 `chart.palaces.kinByShiShen`，引擎已按十神在盘中的分量排好序。

## 执行流程

对每一层 Vk（k = 1…6）：

1. 从 `chart.json` 取出**到 Vk 为止所有已解锁维度**的数据
2. **不看上一版**，从头写一份完整解读，结构固定为：
   - `骨架`：身强弱、五行盈缺
   - `六亲宫`：父母 / 兄弟 / 配偶 / 子女（柱位）+ 亲友长辈（十神）
   - `年龄段`：四段，每段一句
   - `领域`：性格 / 事业 / 财 / 感情 / 健康
3. 写完再取出上一版，逐条 diff，产出 `diff[]` 和 `conflicts[]`
4. 按 `references/schema.json` 的格式输出

V7 对每步大运重复 1–4（把大运干支当作第五柱加进来）。
V8 流年走简化路径。V9 综合。

## 输出格式

见 `references/schema.json`。要点：

```json
{
  "version": "V3",
  "unlockedDimensions": ["身强弱","五行盈缺","宫位·粗读","日支藏干","坐支关系"],
  "reading": { "骨架": {...}, "六亲宫": {...}, "年龄段": [...], "领域": {...} },
  "diff": [{ "path":"六亲宫.配偶", "from":"V2 的说法", "to":"V3 的说法",
             "trigger":"日支亥藏壬(正印0.7)", "why":"..." }],
  "conflicts": [{ "between":["V2","V3"], "issue":"...", "resolution":"以 V3 为主，V2 保留为背景" }]
}
```

每条断语形如：
```json
{ "claim": "...", "confidence": "倾向|多半|一定", "evidence": ["日支 亥 藏 壬(本气·正印·0.7)", "乙坐亥 十二长生「死」"] }
```

## 待补（Dan 尚未提供，先用保守默认）

- **五行「缺/多/少」阈值**：暂定 <10% 为缺、<15% 为少、>30% 为多。
  ⚠️ 这是我拍的默认值，等 Dan 确认。当前用的阈值必须在输出里注明。
- **取用神顺序**（扶抑/调候/通关/病药 先看哪个）：暂按「冬生调候优先，其余扶抑优先」。
- **从格入门条件**：暂定单一五行 ≥60% 且日主无根时才考虑。
- **话术边界**：见 `references/boundaries.md`（当前为保守默认，等 Dan 划线）。

凡是用到上述默认值的断语，必须在 `assumptions` 字段里标出来，方便 Dan 之后一次性校准。
