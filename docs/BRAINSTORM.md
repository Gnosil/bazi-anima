# 八字算命 + 可交互像素动画 —— 架构头脑风暴 v0.1

## 0. 一句话

输入「生辰八字信息」→ 输出一个**可交互的像素小动画**，动画本身就是命盘的可视化 + 你的方法论解读的播放器。

---

## 1. 最核心的设计原则：**「算」和「断」必须分离**

这是整个项目成败的关键。

| | 算（排盘层） | 断（解读层） |
|---|---|---|
| 性质 | 确定性、天文历法计算 | 经验性、流派性、你的方法论 |
| 谁来做 | **纯代码**（Python/JS 脚本） | **Skill + LLM** |
| 错了会怎样 | 全盘皆错，且错得很隐蔽 | 可以讨论、可以调 |

**LLM 绝对不能算干支。** 大模型算年柱会忘立春、算月柱会忘节气、算日柱会直接编。必须由脚本算完，把结构化 JSON 喂给 LLM，LLM 只负责「断」。

已验证可用的引擎（本环境已装好并跑通）：

- `lunar-javascript` (Node) —— 八字四柱、十神、藏干、大运起运、神煞、纳音、旬空，一次性全给。测试用例 1998-11-24 10:30 → `戊寅 癸亥 乙亥 辛巳`，日主乙，大运 2003 甲子 / 2013 乙丑 / 2023 丙寅 ✅
- `sxtwl` (Python) —— 寿星万年历，高精度节气/朔望，用来做交叉校验和真太阳时

## 2. 三层架构

```
┌─ L1 排盘引擎 (engine/)  —— 确定性，可单元测试
│   输入: 生日 + 时辰 + 出生地经纬度 + 性别 + 公历/农历
│   处理: 真太阳时校正 → 干支历 → 四柱 → 十神/藏干/纳音/神煞
│         → 大运（阳男阴女顺逆、起运岁数、交运日期）→ 流年
│         → 刑冲合害会 / 旺衰 / 五行分布量化
│   输出: chart.json   ← 这是整个项目的「中间表示 (IR)」
│
├─ L2 解读层 (skill/)  —— 你的方法论，写成 Skill
│   输入: chart.json
│   处理: 按你的流程走 —— 定强弱 → 取格局 → 定用忌 → 分领域断
│   输出: reading.json （结构化的断语 + 每条断语指向盘中哪个证据）
│
└─ L3 动画层 (anima/)  —— 可交互像素动画
    输入: chart.json + reading.json
    输出: 单文件 HTML（Canvas/p5.js，像素风），可分享、可交互
```

**IR (chart.json) 是关键。** 只要 schema 定死，三层就可以各自独立迭代——换排盘库不影响动画，改方法论不影响排盘。

---

## 3. L1 排盘层 —— 需要跟你确认的细节

这些都是「流派分歧点」，代码里必须做成**可配置开关**，默认值填你的用法：

- [ ] **早晚子时**：23:00–24:00 算今日子时还是次日子时？
- [ ] **真太阳时**：是否做经度校正？是否做均时差校正？（差 30+ 分钟能改时柱）
- [ ] **换月**：严格节气交接时刻，还是节气日？
- [ ] **起运**：3 天折 1 年 / 精确到日时？交运是「生日当天」还是「节气日」？
- [ ] **神煞**：只取常用十几个，还是全上？（神煞太多会淹没主线）
- [ ] **旺衰**：用月令+得地得势打分，还是用你自己的一套权重？
- [ ] **是否用 紫微/大六壬/奇门 做交叉参考**，还是纯八字？

## 4. L2 方法论 Skill —— 我需要你告诉我的

这是你说要提供的部分。为了把它变成一个真能复现你判断的 Skill，我需要这几类东西：

### 4.1 流程（你的 SOP）
你拿到一个盘，第 1 步看什么、第 2 步看什么……到出结论，一共几步？每步的判断依据和排除条件。

### 4.2 规则（可编码的部分）
形如「若 X 且 Y，则倾向 Z」的判断。比如日主强弱怎么定阈值、用神怎么取、什么情况下走从格。

### 4.3 话术（输出风格）
你给人断命时是什么口吻？铁口直断，还是给区间和概率？哪些话不能说（健康、寿命、灾祸的边界在哪）？

### 4.4 案例（最有价值）
**3–5 个你断过的真实案例**：盘 + 你当时的推理过程 + 结论。这比任何抽象规则都管用，Skill 里做成 few-shot，模型模仿你的推理链条。

### 4.5 你现在用的工具
你提到「工作工具调用」—— 具体是哪些？排盘 App？在线万年历？自己的表格？知道了我可以：
- 如果是网页 → 用浏览器自动化对齐结果，做回归测试
- 如果是 App → 至少用它的输出做我们引擎的 ground truth

## 5. L3 动画层 —— 创意方向（这块最好玩）

### 方向 A：命盘即「RPG 存档」🎮 ← 我最推荐
把八字翻译成一个像素 RPG 的角色面板：

- **角色立绘**：日主 = 主角，五行属性决定配色和造型（甲木=树精、丙火=火焰武士…）
- **属性条**：金木水火土五条 HP/MP 风格的像素血条，长度 = 五行力量量化值
- **技能栏**：十神 = 技能图标（正官=盾、七杀=刀、食神=料理、伤官=法杖、正财偏财=钱袋…）
- **Buff/Debuff**：神煞 = 状态图标（桃花、驿马、华盖、天乙贵人）
- **世界地图 / 关卡条**：大运 = 8–10 个关卡，每关一个像素场景，颜色/天气 = 该运吉凶
- **时间轴滑块**：拖动年份 → 场景切换 + 流年事件卡弹出（交互核心）
- **战斗动画**：刑冲合害 = 两个地支精灵之间的像素攻击特效

### 方向 B：命盘即「天象/星图」
更玄学的调性。四柱化为四个星宿，五行流转做成粒子流，大运是轨道公转。冷色、神秘、少字。

### 方向 C：命盘即「像素漫画条」
生成一格格像素分镜，配旁白，像素小人演出人生阶段。最有叙事感，但生成成本最高。

### 技术选型对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| **纯代码生成**（p5.js / Canvas + 手写像素 sprite） | 免费、秒出、100% 可控、可交互、单文件可分享 | 美术上限受限于我写代码的能力 |
| **AI 生成素材 + 代码组装** | 立绘/场景好看很多，仍然可交互 | 需要图像模型；风格一致性要靠 prompt 模板锁 |
| **纯视频生成** | 视觉冲击最强 | 不可交互（和你的需求冲突）、慢、贵、无法精确表达数据 |

**建议：以「纯代码生成」为骨架（保证可交互 + 数据准确），用「AI 生成素材」补皮肤**（60 个天干地支精灵、10 种大运场景背景，一次性生成成 sprite sheet 存进 repo，之后复用，零边际成本）。

## 6. 仓库结构

```
bazi-anima/
├── engine/          L1 排盘引擎 + chart.json schema + 单元测试
├── skill/
│   └── bazi-reading/
│       ├── SKILL.md          你的方法论主流程

├── anima/           L3 动画模板 + sprite 素材
├── cases/           真实案例（盘 + 你的推理 + 结论），回归测试用
└── docs/            设计文档（本文件）
```

## 7. 建议的推进顺序

1. **敲定 chart.json schema** —— 一切的地基
2. **L1 引擎跑通 + 用你的工具做交叉验证**（拿你算过的盘对答案）
3. **收集你的方法论 → 写 SKILL.md**
4. **先做一个丑但能跑的动画原型**（纯代码，验证交互形态）
5. **再补美术**（AI 生成 sprite / 找 MCP）

先做 1–2 还是先做 4 的原型？我倾向**先做 4 的低保真原型**，因为「可交互动画」这个形态一旦看到实物，你对 L1 要输出什么数据的要求会立刻清晰很多。

### 娱乐向带来的两条硬约束

1. **翻译层是一等公民。** 「驿马」不能直接显示，要显示「停不下来 —— 搬家、出差、变动多」。
   翻译表已建在 `anima/design-system/tokens.js` 的 `shenSha`，后续所有术语都走这张表。
2. **话术要留余地。** 娱乐产品的断语一旦说死，用户当真了会出事。健康/寿命/灾祸类断语需要
   在 SKILL.md 里明确定边界。这块等 Dan 的话术规范。
